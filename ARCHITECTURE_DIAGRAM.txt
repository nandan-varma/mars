CRITICAL COUPLING ISSUES
================================================================================

🔴 ISSUE #1: Mouse Driver Globals Exposed
   ├─ Location: os/drivers/mouse_internal.h
   ├─ Exports: 18 global variables via extern
   ├─ Files affected:
   │  ├─ mouse_uefi.c (207L)
   │  ├─ mouse_ps2.c (151L)
   │  ├─ mouse_absolute.c (116L)
   │  └─ mouse_simple.c (117L)
   ├─ Impact: Any module can read/write state directly
   └─ Fix: Provide accessor functions only

🔴 ISSUE #2: App Framework Over-Responsibilities
   ├─ Location: os/kernel/app.c (584 lines)
   ├─ Current: Manages shell + tasks + logs + app framework
   ├─ Should be: Just registry + launching + dispatch (~100 lines)
   ├─ Violates: Single Responsibility Principle
   └─ Fix: Extract shell, tasks, logs as separate apps

🔴 ISSUE #3: Event Packet Structure Exposed
   ├─ Location: os/include/event_bus.h
   ├─ Issue: event_packet_t fully exposed with fixed 64-byte payload
   ├─ Impact: Cannot change payload size without breaking ABI
   └─ Fix: Make opaque handle + builder/accessor functions

⚠️ ISSUE #4: WM Render Too Large
   ├─ Location: os/gui/wm_render.c (486 lines)
   ├─ Concerns:
   │  ├─ Clock rendering (should be separate)
   │  ├─ Debug overlay (should be separate)
   │  ├─ Window rendering (proper)
   │  └─ Mouse cursor (proper)
   ├─ Dependencies: 12 headers
   └─ Fix: Split into wm_render.c + wm_clock.c + wm_debug.c

⚠️ ISSUE #5: Input Driver Mixed Concerns
   ├─ Location: os/drivers/input.c (170 lines)
   ├─ Concerns:
   │  ├─ Polling coordination
   │  ├─ Event serialization (wrong layer)
   │  └─ Publishing (wrong layer)
   └─ Fix: Separate serialization, let WM handle publishing
